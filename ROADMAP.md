# Navisworks MCP — план развития

Сейчас (2.2.1): 63 инструмента MCP, 59 маршрутов плагина, Navisworks Manage/Simulate
2026 и 2027. Плагин запускает мост по кнопке **AI companion → MCP Bridge**; MCP-сервер —
`server_http.py` (Python). Ниже — этапы дальнейшей работы, затем каталог идей
инструментов (из него берутся задачи этапов 2–5) и известные проблемы.

Образец для этапа 1 — проект AutoCAD MCP (`..\AutoCAD_MCP`): сервер
`server\AcadMcpServer`, установщик `installer\INSTALL.BAT`, `Build-Package.ps1`.

Порядок работы (как в AutoCAD MCP): шаг = версия +0.0.1 и короткий коммит, коммит —
только после согласия; в конце этапа — минорная версия, README, коммит и push.

## Этапы разработки

### Этап 1 — MCP-сервер на .NET и новый установщик → 2.3.0

Версия 2.3.0 выходит, когда готовы обе части: сервер на .NET и установщик, который его
ставит и подключает к агентам. Промежуточные шаги — 2.2.x.

#### 1а. MCP-сервер на .NET вместо Python

Отдельная программа, как сейчас `server_http.py`: агент запускает её, она ходит в плагин
по HTTP. Плагин не меняется, кроме `/health`.

- [ ] Проект `server\NavisMcpServer`: net8.0, `RollForward=Major`, без apphost и без
  NuGet → `navis_mcp_server.dll`, запуск `dotnet.exe navis_mcp_server.dll`. Не .exe:
  на этом ПК контроль приложений блокирует неподписанные .exe в папках пользователя.
  Основа — `McpServer.cs`, `Bridge.cs`, `Registration.cs` из `AcadMcpServer`.
- [ ] `tools.json` (встроенный ресурс) — единственный источник описаний всех 63
  инструментов; перенести из `TOOLS` / `ROUTES` / `PARAM_MAP` в `server_http.py`.
  Решить: держать переименование аргументов (`test_name` → `name`) в `tools.json`
  или привести имена в плагине к именам инструментов и убрать переименование.
- [ ] Перенести поведение `server_http.py`: порт 8765 (переменная `NAVIS_MCP_PORT`),
  тайм-аут 30 с и 1 ч для долгих маршрутов (`LONG_ROUTES`), `image_png_base64` →
  картинка MCP, ошибки плагина → `isError: true`, запросы обрабатываются параллельно.
- [ ] Плагин: `/health` отдаёт `product: "Navisworks"`; сервер проверяет, что на порту
  именно мост Navisworks (как проверка `product` в AutoCAD MCP).
- [ ] `instructions` сервера: мост запускается кнопкой AI companion → MCP Bridge;
  модальные окна Navisworks блокируют вызовы.
- [ ] Самрегистрация: `--register` / `--unregister claude-desktop | claude-code | codex | all`,
  резервная копия конфига перед первым изменением. Имя сервера остаётся `navisworks`
  (на него опираются `/fm-update` и уже настроенные агенты).
- [ ] Проверка: тест на уровне MCP по stdio (`initialize`, `tools/list` = 63,
  вызов с картинкой, вызов с ошибкой) + `tests\smoke_test.py` 57/57 на 2026 и 2027;
  Claude Desktop видит и вызывает инструменты.
- [ ] Убрать `server_http.py` из бандла и репозитория; Python остаётся только для тестов.

Среда выполнения: Navisworks 2026 и 2027 сами ставят .NET (их загрузчики Revit-файлов
требуют .NET 10 и .NET 8), так что .NET 8+ есть везде, где есть Navisworks. Установщик
всё равно проверяет.

#### 1б. Установщик как у AutoCAD MCP

Подготовку пакета (первые два пункта) можно делать параллельно с сервером; регистрация
в агентах и удаление Python-сервера — после него.

- [ ] `Build-Package.ps1`: собирает плагин 2026 + 2027 и сервер, версия из одного места
  (плагин, бандл, сервер); `release\Navisworks_MCP_<ver>\` = `INSTALL.BAT`,
  `MCPBridge.bundle.zip`, `RELEASE.md`, `README.md`; архив каждой версии остаётся в `release\`.
- [ ] `INSTALL.BAT`: язык EN/RU; находит Manage/Simulate 2026/2027; требует закрыть
  Navisworks; ставит бандл в `%ProgramData%\Autodesk\ApplicationPlugins` (проверено:
  Navisworks грузит оттуда), сервер — в `Contents\Server\`; показывает установленную версию.
- [ ] Удаляет старое: копии плагина вне бандла (уже умеет), `server_http.py` из бандла,
  записи `navisworks` в конфигах агентов, которые запускают `server_http.py` (заменяет
  новым сервером). Пакет Python `mcp` не трогать — он может быть нужен другим программам.
- [ ] Предлагает подключить сервер к агентам по одному: Claude Desktop, Claude Code, Codex.
- [ ] Проверяет .NET 8+ (`dotnet --list-runtimes`) и объясняет, что делать, если его нет.
- [ ] `INSTALL.BAT /uninstall`: удаляет бандл и записи `navisworks` в агентах.
- [ ] Переменные для тестов (как `ACADMCP_*`): папка бандла, конфиги Claude/Codex,
  «не трогать агентов». Тестировать только в песочнице, с подменой путей в тексте.
- [ ] `RELEASE.md` на русском и английском; README — установка из релиза.

## Известные проблемы

- **`zoom_to_clash` ставит камеру слишком близко** к маленьким коллизиям — кадр почти
  целиком занят элементом. `Viewpoint.ZoomBox` игнорирует отступ; попробовать задать
  положение камеры самим (центр коллизии + расстояние по размеру бокса).
- **Полный обход модели опасен на больших федеративных моделях:** `find_items_by_name`
  на модели 1,9 ГБ уронил Navisworks (обходил всю геометрию). Для файлов есть
  `select_files` / `color_files`; поиску по элементам нужен лимит или прерывание.

## История версий

**Версия 2.2 (2026-10-27):** сделаны управление моделями (`list_model_files`,
`open_document`, `new_document`, `append_files`, `remove_file`, `update_files`,
`save_document`, `publish_nwd`, `convert_to_nwd`) и пункты 1–2. `assign_clash` вышел
как `assign_clashes`, `refresh_models` — как `update_files`, даты файлов — в
`list_model_files`; `run_all_clash_tests` не нужен: `run_clash_test` без имени
запускает все проверки. Проверка: `tests/smoke_test.py`, 57/57 на 2026 и 2027.

**Версия 2.2.1 (2026-10-28):** `select_files` / `color_files` — подмодели по имени файла
через обход только дерева файлов (как `get_model_tree`). `find_items_by_name` на
федеративной модели 1,9 ГБ обходил всю геометрию и уронил Navisworks.

## Каталог инструментов

Идеи по убыванию пользы; `[x]` — сделано. Названия методов Navisworks API перед
реализацией нужно проверить. Каждый новый инструмент = обработчик в плагине (файл
своей области, `*Handlers.cs`) + описание и маршрут в MCP-сервере (сейчас
`server_http.py`, после этапа 1 — `tools.json`) → пересобрать 2026 и 2027 → обновить
бандл.

### Первая очередь

- [x] `capture_view` + `zoom_to_elements` — дают Claude «зрение»
- [x] `set_clash_result_status` + `zoom_to_clash` — главный пробел в работе с коллизиями
- [ ] `list_property_values` — мало кода, заметно точнее поиск

### 1. Чтобы Claude видел модель

- [x] **`capture_view`** — снимок текущего вида (PNG) в чат. Сейчас Claude
  раскрашивает и изолирует вслепую; со снимком может проверить результат и описать
  коллизию по картинке.
- [x] **`zoom_to_elements`** — навести камеру на элементы. Частый шаг после поиска,
  сейчас нужны сохранённые видовые точки.
- [x] **`set_section_box`** — секущий бокс вокруг элементов или уровня: внутри здания
  без сечения почти ничего не видно.

### 2. Полный цикл работы с коллизиями

- [x] **`set_clash_result_status`, `assign_clash`, `add_clash_comment`** — статус,
  ответственный, комментарий у отдельной коллизии (сейчас статус только у групп).
- [x] **`zoom_to_clash`** — показать коллизию как Clash Detective (камера + подсветка
  двух элементов). С `capture_view`: «покажи 10 самых крупных коллизий и опиши».
- [x] **`get_clash_summary`** — число коллизий по статусам для каждой проверки, без
  выгрузки тысяч результатов.
- [x] **`auto_group_clashes`** — автогруппировка по уровню / файлу / элементу / осям
  одним вызовом.
- [x] **`export_clash_report`** — отчёт HTML / XML / CSV для подрядчиков.
- [x] **`run_all_clash_tests`** — перезапуск всех проверок одной командой.

### 3. Свойства и поиск без угадывания

- [ ] **`list_property_values`** — уникальные значения свойства (все категории, все
  уровни). Убирает угадывание точных имён при создании поисковых наборов.
- [ ] **`list_property_names`** — какие категории и свойства вообще есть в модели.
- [ ] **`find_items` с несколькими условиями (И/ИЛИ)** — например «трубы DN>100 на 3 этаже».
- [ ] **`export_properties`** — свойства многих элементов в CSV: проверки качества
  (пустые параметры), спецификации.

### 4. Управление моделями

- [x] **`refresh_models`, `append_model`, `save_document`** — обновить подгруженные
  файлы, добавить файл, сохранить NWF/NWD. Связка с еженедельным `/ifc-update`:
  скопировали IFC → обновили модели → перезапустили проверки → отчёт.
- [x] **`get_model_tree` с датами файлов** — видно, какие модели устарели.
- [ ] **`get_model_transform` / `set_model_transform`** — то же, что диалог
  «Units and Transform»: прочитать и задать единицы, смещение (origin), поворот
  (ось + угол), масштаб и отражение для модели верхнего уровня (по индексу или имени,
  как `remove_file`). API: чтение — `Model.Units`, `Model.Transform`; запись —
  `DocumentModels.SetModelUnitsAndTransform(model, units, transform, reflected)`.
  Ограничения: только модели из `list_model_files` (отдельный IFC — в листовом NWF,
  в сборщике двигается дочерняя NWD целиком); трансформация хранится в NWF/NWD —
  нужно сохранить и пересобрать родителей вверх. Пригодится в `/fm-update`, когда
  IFC приходит со смещённой точкой вставки.
