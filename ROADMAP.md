# Navisworks MCP — идеи новых инструментов

Сейчас в MCP 40 инструментов (поиск, выделение, раскраска, наборы, видовые точки,
проверки коллизий и группы). Ниже — чего не хватает, по убыванию пользы.
Названия методов Navisworks API перед реализацией нужно проверить.

**Версия 2.2 (2026-10-27):** сделаны управление моделями (`list_model_files`,
`open_document`, `new_document`, `append_files`, `remove_file`, `update_files`,
`save_document`, `publish_nwd`, `convert_to_nwd`) и пункты 1–2. `assign_clash` вышел
как `assign_clashes`, `refresh_models` — как `update_files`, даты файлов — в
`list_model_files`; `run_all_clash_tests` не нужен: `run_clash_test` без имени
запускает все проверки. Проверка: `tests/smoke_test.py`, 57/57 на 2026 и 2027.

Известное: при `zoom_to_clash` камера встаёт очень близко к маленьким коллизиям.

Каждый новый инструмент = обработчик в `MCPBridgePlugin.cs` + описание и маршрут
в `server_http.py` → пересобрать 2026 и 2027 → обновить `release\MCPBridge.bundle`.

## Первая очередь

- [x] `capture_view` + `zoom_to_elements` — дают Claude «зрение»
- [x] `set_clash_result_status` + `zoom_to_clash` — главный пробел в работе с коллизиями
- [ ] `list_property_values` — мало кода, заметно точнее поиск

## 1. Чтобы Claude видел модель

- [x] **`capture_view`** — снимок текущего вида (PNG) в чат. Сейчас Claude
  раскрашивает и изолирует вслепую; со снимком может проверить результат и описать
  коллизию по картинке.
- [x] **`zoom_to_elements`** — навести камеру на элементы. Частый шаг после поиска,
  сейчас нужны сохранённые видовые точки.
- [x] **`set_section_box`** — секущий бокс вокруг элементов или уровня: внутри здания
  без сечения почти ничего не видно.

## 2. Полный цикл работы с коллизиями

- [x] **`set_clash_result_status`, `assign_clash`, `add_clash_comment`** — статус,
  ответственный, комментарий у отдельной коллизии (сейчас статус только у групп).
- [x] **`zoom_to_clash`** — показать коллизию как Clash Detective (камера + подсветка
  двух элементов). С `capture_view`: «покажи 10 самых крупных коллизий и опиши».
- [x] **`get_clash_summary`** — число коллизий по статусам для каждой проверки, без
  выгрузки тысяч результатов.
- [x] **`auto_group_clashes`** — автогруппировка по уровню / файлу / элементу / осям
  одним вызовом.
- [x] **`export_clash_report`** — отчёт HTML / XML / CSV для подрядчиков.
- [x] **`run_all_clash_tests`** — перезапуск всех проверок одной командой.

## 3. Свойства и поиск без угадывания

- [ ] **`list_property_values`** — уникальные значения свойства (все категории, все
  уровни). Убирает угадывание точных имён при создании поисковых наборов.
- [ ] **`list_property_names`** — какие категории и свойства вообще есть в модели.
- [ ] **`find_items` с несколькими условиями (И/ИЛИ)** — например «трубы DN>100 на 3 этаже».
- [ ] **`export_properties`** — свойства многих элементов в CSV: проверки качества
  (пустые параметры), спецификации.

## 4. Управление моделями

- [x] **`refresh_models`, `append_model`, `save_document`** — обновить подгруженные
  файлы, добавить файл, сохранить NWF/NWD. Связка с еженедельным `/ifc-update`:
  скопировали IFC → обновили модели → перезапустили проверки → отчёт.
- [x] **`get_model_tree` с датами файлов** — видно, какие модели устарели.

## 5. Полезно, но реже нужно

- [ ] **`measure_distance`** — минимальное расстояние между элементами / наборами
  (зазоры, монтажные допуски).
- [ ] **Комментарии и пометки на видовых точках, папки видовых точек** — материалы
  к совещаниям.
- [ ] **Timeliner (`list_tasks`, `link_set_to_task`)** — 4D; узкая задача, отдельный API.
