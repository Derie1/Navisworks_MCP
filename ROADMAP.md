# Navisworks MCP — план развития

Сейчас (2.4.0): 66 инструментов MCP, 62 маршрута плагина, Navisworks Manage/Simulate
2026 и 2027. Плагин запускает мост по кнопке **AI companion → MCP Bridge**; MCP-сервер —
`navis_mcp_server.dll` (.NET), ставится и подключается к агентам установщиком `INSTALL.BAT`. Ниже — этапы дальнейшей работы, затем каталог идей
инструментов (из него берутся задачи этапов 2–4), отложенное и известные проблемы.

Образец для этапа 1 — проект AutoCAD MCP (`..\AutoCAD_MCP`): сервер
`server\AcadMcpServer`, установщик `installer\INSTALL.BAT`, `Build-Package.ps1`.

Порядок работы (как в AutoCAD MCP): шаг = версия +0.0.1 и короткий коммит, коммит —
только после согласия; в конце этапа — минорная версия, README, коммит и push.

## Этапы разработки

### Этап 1 — MCP-сервер на .NET и новый установщик → 2.3.0 — выполнен

Версия 2.3.0 выходит, когда готовы обе части: сервер на .NET и установщик, который его

#### 1а. MCP-сервер на .NET вместо Python

Отдельная программа, как сейчас `server_http.py`: агент запускает её, она ходит в плагин
по HTTP. Плагин не меняется, кроме `/health`.

- [x] Проект `server\NavisMcpServer`: net8.0, `RollForward=Major`, без apphost и без
  NuGet → `navis_mcp_server.dll`, запуск `dotnet.exe navis_mcp_server.dll`. Не .exe:
  на этом ПК контроль приложений блокирует неподписанные .exe в папках пользователя.
  Основа — `McpServer.cs`, `Bridge.cs`, `Registration.cs` из `AcadMcpServer`.
- [x] `tools.json` (встроенный ресурс) — единственный источник описаний всех 63
  инструментов; перенести из `TOOLS` / `ROUTES` / `PARAM_MAP` в `server_http.py`.
  Решить: держать переименование аргументов (`test_name` → `name`) в `tools.json`
  или привести имена в плагине к именам инструментов и убрать переименование.
- [x] Перенести поведение `server_http.py`: порт 8765 (переменная `NAVIS_MCP_PORT`),
  тайм-аут 30 с и 1 ч для долгих маршрутов (`LONG_ROUTES`), `image_png_base64` →
  картинка MCP, ошибки плагина → `isError: true`, запросы обрабатываются параллельно.
- [x] Плагин: `/health` отдаёт `product: "Navisworks"`; сервер проверяет, что на порту
  именно мост Navisworks (как проверка `product` в AutoCAD MCP).
- [x] `instructions` сервера: мост запускается кнопкой AI companion → MCP Bridge;
  модальные окна Navisworks блокируют вызовы.
- [x] Самрегистрация: `--register` / `--unregister claude-desktop | claude-code | codex | all`,
  резервная копия конфига перед первым изменением. Имя сервера остаётся `navisworks`

- [x] Проверка: тест на уровне MCP по stdio (`initialize`, `tools/list` = 63,

Среда выполнения: Navisworks 2026 и 2027 сами ставят .NET (их загрузчики Revit-файлов
требуют .NET 10 и .NET 8), так что .NET 8+ есть везде, где есть Navisworks. Установщик
всё равно проверяет.

### Этап 2 — положение моделей → 2.4.0 — выполнен

То, что делает диалог **Units and Transform**, — для `/fm-update`, когда IFC приходит со
смещённой точкой вставки. API: чтение — `Model.Units`, `Model.Transform`
(`Transform3D.Factor()` → смещение, поворот, масштаб); запись —
`DocumentModels.SetModelUnitsAndTransform(model, units, transform, reflected)`.

- [x] **`get_model_transform`** — для одной модели (по номеру или имени, как
  `remove_file`) или всех: единицы, смещение XYZ, поворот (угол в градусах + ось),
  масштаб XYZ, отражение, есть ли трансформация; габариты модели (min / max / центр) —
  по ним видно «уехавший» IFC.
- [x] **`set_model_transform`** — единицы, смещение, поворот (угол вокруг оси, по
  умолчанию Z), масштаб, отражение; передаются только меняемые. Режимы «задать» и
  «добавить к текущему». В ответе положение «до» и «после».
- [x] **`reset_model_transform`** — вернуть положение, в котором мост впервые увидел модель
  в открытом документе. Не «в ноль»: в трансформации IFC уже лежит его геопривязка
  (например, 685198 / 5379841 / 434 м), сброс в ноль увёз бы модель к началу координат.
- [x] Ошибки с подсказкой: файл внутри NWD двигать нельзя — открыть NWF, из которого
  собран NWD. Описание: после изменения сохранить документ и пересобрать родителей;
  смена единиц масштабирует модель.
- [x] Проверка: `smoke_test.py` — прочитать, сдвинуть, повернуть, сбросить, габариты
  меняются на нужную величину, после сохранения и переоткрытия NWF положение на месте;
  `mcp_server_test.py`; Navisworks 2027 и 2026.

Отложено: перемещение отдельных элементов (Item Tools → Transform,
`OverridePermanentTransform` / `ResetPermanentTransform`) — для обновления федеративной
модели не нужно.

## Отложено

### Пакетная работа без окна Navisworks (отложено: острой необходимости нет)

Аналог `batch_run` в AutoCAD MCP: Navisworks Automation API
(`Autodesk.Navisworks.Automation`) запускает скрытый Navisworks из внешней программы —
открыть NWF, обновить, сохранить NWD, запустить проверки — без нажатия кнопки моста.
Пригодится для ночной пересборки федеративной модели.

## Известные проблемы

- **`zoom_to_clash` ставит камеру слишком близко** к маленьким коллизиям — кадр почти
  целиком занят элементом. `Viewpoint.ZoomBox` игнорирует отступ; попробовать задать
  положение камеры самим (центр коллизии + расстояние по размеру бокса).
- **Полный обход модели опасен на больших федеративных моделях:** `find_items_by_name`
  на модели 1,9 ГБ уронил Navisworks (обходил всю геометрию). Для файлов есть
  `select_files` / `color_files`; поиску по элементам нужен лимит или прерывание.

### 4. Управление моделями

- [x] **`refresh_models`, `append_model`, `save_document`** — обновить подгруженные
  файлы, добавить файл, сохранить NWF/NWD. Связка с еженедельным `/ifc-update`:
  скопировали IFC → обновили модели → перезапустили проверки → отчёт.
- [x] **`get_model_tree` с датами файлов** — видно, какие модели устарели.
- [x] **`get_model_transform` / `set_model_transform`** — то же, что диалог
  «Units and Transform»: прочитать и задать единицы, смещение (origin), поворот
  (ось + угол), масштаб и отражение для модели верхнего уровня (по индексу или имени,
  как `remove_file`). API: чтение — `Model.Units`, `Model.Transform`; запись —
  `DocumentModels.SetModelUnitsAndTransform(model, units, transform, reflected)`.
  Ограничения: только модели из `list_model_files` (отдельный IFC — в листовом NWF,
  в сборщике двигается дочерняя NWD целиком); трансформация хранится в NWF/NWD —
  нужно сохранить и пересобрать родителей вверх. Пригодится в `/fm-update`, когда
  IFC приходит со смещённой точкой вставки.
